## Regras de arquitetura
- `src/features/*` = domínio e funcionalidade
- `src/lib/*` = infraestrutura transversal
- `src/config/*` = configuração
- `src/app/*` = bootstrap, providers, router
- `src/layouts/*` = layouts globais
- `src/shared/components/*` = componentes reutilizáveis sem conhecimento de domínio
- `src/shared/hooks/*` = hooks reutilizáveis transversais
- `src/shared/types/*` = tipos partilhados
- `src/shared/styles/*` = estilos globais

## Regras de organização
- Respeita sempre a package structure fornecida
- Não cries ficheiros fora da árvore sem eu pedir
- Se um ficheiro estiver marcado com `X`, assume que existe mas está vazio
- Só cria/altera os ficheiros necessários nesta iteração
- Não faças refactors globais sem eu pedir
- Se o código vier misturado, separa UI, lógica, API, tipos e mappers nos locais corretos
- Componentes de negócio ficam na feature respetiva, nunca em `shared`
- Não inventes imports, dependências, aliases, ficheiros ou APIs que não existam no contexto dado
- Se faltar contexto, diz exatamente o que falta

## Regras de implementação
- Usa TypeScript estrito
- Evita `any`
- Prefere código simples, coeso e legível
- Evita overengineering
- Evita ficheiros gigantes
- Remove ou isola mock data
- Melhora naming quando necessário
- Extrai hooks/helpers apenas quando fizer sentido
- Se houver contratos REST fornecidos, usa-os como fonte de verdade
- Se eu enviar endpoints e DTOs do backend, deves adaptar o código a eles

## Auth
- `features/auth` = experiência de autenticação
- `lib/auth` = tokens, sessão, refresh, permissões
- `lib/api` = HTTP client, interceptors, erros, integração com API
- Nunca espalhes lógica de autenticação por componentes aleatórios
